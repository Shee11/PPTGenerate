Old‑school AI workflow

Who did what back then?

  • Linear pipeline: data → model → training → deploy
  • Each stage owned by a different team
  • Months of data prep and tuning
  • Infra, eval, optimization rebuilt every project
  • Progress slow, expensive, and siloed
  • Data engineers: collect, clean, pipeline data
  • ML scientists: design models, chase accuracy
  • Dev/infra engineers: deploy, scale, keep lights on
  • PMs: juggle handoffs across siloed stages
  • Everyone reinvents infra and eval each time

Vibe: slow, infra‑heavy, rigid

  • Months to ship features
  • High barrier for individual devs
  • Little reuse across projects

How Reliable LLM Apps Are Really Built

  • Start with a general prompt for ~90% of cases
  • Test on many realistic examples, log failures
  • Patch edge cases with explicit constraints, clarifications
  • Repeat until only the last 10% are tricky
  • LLM plans: decides high‑level steps
  • Deterministic tools execute and validate
  • Feedback prevents errors from compounding
  • Prompts + architecture beat prompts alone
  • Think in loops: prompts + evaluation
  • Design planner–executor workflows, not single prompts
  • Instrument telemetry for fast, automatic refinement
  • Combine LLMs, tools, and validators for reliability

Spec → Slides → Docs → Diagrams → Code: One Source, All Outputs

  • 1️⃣ Write a tight spec: scope, goals, structure
  • 2️⃣ Ask LLM: "Turn this spec into a slide deck"
  • 3️⃣ Reuse same spec: "Generate a detailed design doc"
  • 4️⃣ From spec: "Create Mermaid diagrams for this flow"
  • 5️⃣ From spec: "Draft code skeletons for the main components"
  • All artifacts stay synced to the same spec
  • Practice precise specs, not just prompts
  • Let AI handle translations between formats
  • Iterate on the spec, not scattered files
