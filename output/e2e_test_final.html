How AI work is changing

Then: Linear AI pipeline

Now: LLM‑centric AI work

  • Fixed roles: data → model → deployment
  • Data engineers owned data quality
  • ML scientists maximized accuracy
  • Developers chased latency, throughput
  • PMs measured user impact, funnels
  • Slow, expensive, infra reinvented
  • Large models as unified knowledge base
  • Reasoning interface instead of fixed stages
  • From bespoke models to composition
  • Prompting, lightweight orchestration, tools
  • Roles blur across data, product, infra
  • Focus shifts to application behavior

Old world: specialize in one pipeline stage and hand off work between roles.

LLM world: collaborate across stages, compose systems, and own end‑to‑end behavior.

Key takeaway: expect blurred role boundaries as LLMs become the core building block.

Building reliable LLM systems: beyond prompt tuning

Prompts: necessary, not enough

Why prompts hit a wall

Introduce planner–executor pattern

How this helps you build

  • Design prompt for ~90% cases
  • Then iterate on real failures
  • Explicitly encode constraints, avoidances
  • Prompt tuning alone can’t stop hallucinations
  • Errors accumulate across multi-step workflows
  • Need architecture, not just better wording
  • LLM planner: high-level reasoning, action sequence
  • Code/tools executor: strict guardian, real state
  • Executor validates steps, signals failures back
  • Feedback loop prevents compounding errors
  • Treat prompts as components, not magic
  • Add planner–executor to your toolbox
  • Use architecture to control error accumulation

For devs: combine iterative prompt work with planner–executor architectures to tame errors.

Human edges in the AI era

Where humans still beat LLMs

Human edge #1: low‑level tuning

  • Hand‑tuned C++ and intrinsics
  • Memory and cache‑aware decisions
  • LLMs still weak at this

Human edge #2: scoping

  • Find the real bottleneck first
  • System‑level impact over micro‑wins
  • Example: 38x/sec vs once

Action: practice low‑level tuning and always question whether optimizations matter at system level.

Single-spec workflow with LLM tools

LLMs as daily translators

Use LLMs to translate one clear spec into slides, docs, diagrams, and code scaffolds.

  • Write concise natural-language spec
  • Keep spec as single truth
  • Work inside IDE (e.g., VS Code)
  • Generate PPT slides from spec
  • Create Word design document
  • Produce Mermaid → PNG diagrams

Treat LLMs as translators between slides, docs, diagrams, and future code structure.
