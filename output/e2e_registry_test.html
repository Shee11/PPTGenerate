Traditional AI: Linear, role-separated pipeline

Linear traditional AI pipeline

1. Data collection

2–3. Model + training

4–5. Serving + product

Data collection → model design → training → serving → product impact, each owned by separate teams.

  • Collect and curate data
  • Ensure coverage and quality
  • Owned by data engineers
  • Select or design model structure
  • Train and tune for accuracy
  • Owned by ML/science team
  • Build serving for latency/throughput
  • Measure user and product metrics
  • Owned by dev/infra and product
  • Slow, expensive, reinvents infra/eval

Baseline many org structures still mirror: clear handoffs, but slow and costly.

From prompt tweaks to robust architectures

Building more reliable LLM systems

  • Start with a general prompt
  • Cover ~90% common cases first
  • Target typical developer workflows
  • Collect edge cases, failures
  • Refine prompt to handle them
  • Iterate until residual ~10% acceptable
  • LLM planner: set goals, steps
  • Executor: code enforces constraints, state
  • Persist actions as structured data
  • Validate steps, trigger replanning

Prompt tuning reduces errors but isn’t enough; add planner–executor separation and verification.

Use prompts for common paths, and architecture for planner–executor, validation, and state.

Actionable pattern: iterate on prompts, then add planner–executor and verification to stop error cascades.
