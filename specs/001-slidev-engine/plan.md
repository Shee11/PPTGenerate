## Summary

Create Slidev layout engine that implements the LayoutEngine protocol to provide LLM-friendly layout documentation and a Slidev markdown renderer that converts slide JSON (from existing content generation pipeline) to Slidev-compatible markdown with Vue components. Technical approach: (1) Python LayoutEngine implementation with slot-based layout documentation, (2) JSON→Markdown renderer using Jinja2 templates, (3) Vue/Slidev project with theme-aware components and CSS variable theming.

## Technical Context

**Language/Version**: Python 3.11+ (backend), JavaScript/Vue 3 (frontend Slidev components)  
**Primary Dependencies**: pydantic, jinja2 (Python); Slidev, Vue 3, UnoCSS (JavaScript)  
**Storage**: File-based (.md output files)  
**Testing**: pytest (unit, integration, contract tests following existing test patterns)  
**Target Platform**: Cross-platform (Python backend generates .md, Slidev CLI renders to web)
**Project Type**: Hybrid - Python library for rendering + JavaScript/Slidev project for presentation  
**Performance Goals**: <500ms to render 10-slide presentation JSON to Markdown (SC-003)  
**Constraints**: Must implement LayoutEngine protocol, reuse existing slide JSON schema, <100ms theme switching (SC-002)  
**Scale/Scope**: 3 layouts (smart-grid, hero-split, full-bleed), 2 themes (business, cyber), 3-5 Vue components

**Key Design Decisions**:
1. **Separate Python and Vue Projects**: Python handles JSONMarkdown transformation, Vue/Slidev handles presentation rendering
2. **Jinja2 Templates**: Enable clean separation of rendering logic from string manipulation
3. **No Strategy Pattern**: Slidev engine doesn't need layout strategies (Vue components handle layout)
4. **Coexistence**: Slidev engine lives alongside dummy engine via LayoutEngineRegistry (no removal of existing code)

### Data Flow

1. **Content Generation** (existing pipeline):
   - LLM calls `SlidevLayoutEngine.get_layout_documentation()`
   - Receives layout names, slot names, widget types, themes
   - Generates slide JSON with correct structure

2. **Rendering** (new Slidev renderer):
   - `SlidevRenderer.render(slide_json)` called
   - Frontmatter generated from layout, parameters, theme
   - Widgets mapped to slots based on type (Type.*  markdown, Data.*  components)
   - Output: Slidev markdown file

3. **Presentation** (Slidev CLI):
   - Developer runs `slidev slides.md`
   - Slidev parses frontmatter, loads Vue layouts
   - Vue components render with theme CSS variables
   - Result: Interactive web presentation

### Technology Stack

| Layer | Technology | Purpose |
|-------|-----------|---------|
| Content Generation | Python 3.11+, OpenAI API | LLM-driven slide content generation (existing) |
| Layout Engine | Python, LayoutEngine protocol | Provide layout documentation for LLM |
| Renderer | Python, Jinja2 | Transform JSON to Slidev markdown |
| Presentation | Slidev, Vue 3, UnoCSS | Render markdown as web presentation |
| Components | Vue 3 SFC, TypeScript | Reusable UI components (MetricCard, etc.) |
| Styling | UnoCSS, CSS Variables | Theme-aware styling system |

## Risk Assessment

| Risk | Impact | Likelihood | Mitigation |
|------|--------|-----------|------------|
| LLM generates invalid slot names | High (rendering fails) | Medium | Clear documentation examples, validation in renderer |
| Slidev CLI API changes | Medium (breaking changes) | Low | Pin Slidev version, test with specific version |
| Performance <500ms not met | Low (degrades UX) | Low | Jinja2 caching, batch processing, profiling |
| Theme variable conflicts | Medium (styling breaks) | Low | Scoped CSS variables, component isolation |
| Vue component prop mismatches | High (components fail) | Medium | TypeScript interfaces, prop validation |
