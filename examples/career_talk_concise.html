Know Its Limits

Error Accumulation Risk

Planner–Executor Pattern

  • Start with a general prompt for the common path (~90%)
  • Test on diverse examples to find failures
  • Add explicit constraints for edge cases
  • Repeat until common and critical paths are acceptable
  • Prompt tuning reduces errors but is not a silver bullet
  • Cannot guarantee correctness in every scenario
  • Design systems assuming occasional model mistakes
  • Small inaccuracies compound over multiple steps
  • Long chains of LLM calls can drift into garbage outputs
  • Need architecture patterns that constrain this drift
  • LLM plans high-level steps in structured form
  • Executors (tools/code) perform and track real state
  • Executors validate steps and signal failures
  • Planner revises steps based on real-time feedback
