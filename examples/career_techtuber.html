From Building Models to Composing Systems

With large models, instead of constructing every component from scratch, developers act as "composers" who build applications through prompting and lightweight orchestration.

The focus has shifted from building standalone models to combining existing models, and from model training accuracy to user experience and iteration speed.

In the LLM era, application development emphasizes fast iteration and automated feedback loops rather than heavy training pipelines.

Traditional AI Workflow

  1. Collect data for the target problem.
  2. Select or design the model structure based on the data and task.
  3. Train the model using the collected data and chosen structure.
  4. Deploy the trained model into a production system.

LLM‑Era Composition Workflow

  1. Start from existing large models that act as unified knowledge bases with reasoning interfaces.
  2. Define the user experience and high‑level product goals rather than training a new standalone model.
  3. Design prompts and agent architectures that orchestrate how components invoke models, tools, and context.
  4. Implement lightweight orchestration logic to compose existing models into an application.
  5. Iterate quickly based on user feedback and evaluation, refining prompts and workflows.

Where the Work Actually Moved

  • Micro‑level algorithm optimization work is shifting toward prompt strategy and workflow design.
  • Within application development, work has migrated from training pipelines to designing prompts and agent architectures that decide how components invoke models, tools, or context.
  • Module development has shifted from building clearly bounded modules to orchestrating existing components.
  • Modern AI applications integrate automated feedback loops at runtime to enable automatic refinement and fast iteration.
  • Process optimization is shifting from squeezing the last fraction of model accuracy to integrating systems with telemetry and adaptive loops that better meet customer needs.

Prompt Tuning Like a Systems Engineer

Chao’s practical prompt‑tuning approach is to first define a general prompt that works for about 90% of cases, then iteratively add constraints to handle edge cases and avoid the last 10% of failures.

Chao views success in prompt‑based projects as resolving the last 10% of bad cases, not just making the first 90% work.

Prompt tuning is not a silver bullet and cannot solve all hallucination or error problems.

  • Chao identifies error accumulation as a key challenge in large‑model systems: small errors can compound into garbage outputs.
  • To mitigate error accumulation, Chao advocates a planner‑executor architecture where the LLM does high‑level reasoning as a planner and non‑LLM executors guard and verify each step.

Planner‑Executor Pattern

  1. Use an LLM as a high‑level planner to generate a sequence of actions or a plan for a task.
  2. Represent each planned action in a structured, persistent format rather than only as LLM context.
  1. Implement executors—deterministic components or tools—that interpret and execute each structured action while maintaining precise state.
  2. After each action, have executors verify whether the action succeeded and update state accordingly.
  1. If an action fails verification, feed this feedback to the planner to retry or generate an alternative plan.
  2. Repeat planning and execution steps until the overall task is completed or deemed impossible, limiting error accumulation at each step.

Runtime Feedback & Fast Iteration

  • Modern AI applications integrate automated feedback loops at runtime to enable automatic refinement and fast iteration.
  • In the LLM era, application development emphasizes fast iteration and automated feedback loops rather than heavy training pipelines.
  • Process optimization is shifting from squeezing the last fraction of model accuracy to integrating systems with telemetry and adaptive loops that better meet customer needs.
  • The planner‑executor architecture provides real‑time feedback and verification: if a plan cannot be executed successfully, the system retries or chooses another plan.
